# Alpha14 UI/UX implementation plan

> Execution: Codex 1 implements serially; read-only independent review. Direct user blueprint supplies the approved design and implementation method.

**Goal:** Make real existing RoutineAlarm operations discoverable through an accessible, themed five-destination Android View shell, then replace each screen incrementally.

**Architecture:** Classic Android Views; MainActivity remains lifecycle/action host. Stateless design/components/shell consume display state and callbacks. Existing authority, journal, scheduling, recovery and output code remain authoritative.

**Spec:** R52-ROUTINEALARM-ALPHA14-UIUX-BLUEPRINT/1.0 and R52-CODEX1-ALPHA14-UIUX-LIVING-COMMAND-SURFACE/1.0, copied with hashes to the task evidence directory.

## Global constraints

- Base fd1f5925a6c54a4dd5ef1420b26e3f0f23929e36, isolated codex/routinealarm-alpha14-uiux. Frozen release untouched.
- No Compose, database, scheduler, journal, worker or authority changes. No fabricated AI features or physical delivery status.
- Preserve all 608 existing test cases. No publishing a partial UI as the completed blueprint.
- Minimum 48dp touch targets, 200% font support, text plus non-color status, dark and light palettes.

## Review focus

1. Navigation or recreation must not activate a paused schedule.
2. A late status load must not replace a newly selected destination.
3. Large fonts and narrow widths must retain access to every destination.
4. Restoring invalid UI state must safely fall back without an alarm action.
5. Theme changes must retain navigation/day selection and readable foregrounds.
